Local-first storage

Projects, references, screening decisions, protocols and datasets are kept in your browser's IndexedDB. All statistics, signal processing, meta-analysis and power calculations run locally (heavy work in a Web Worker). Participant-level rows are never sent over the network by the application; they leave the device only if you export them.

Content-Security-Policy

Every page is served with a strict CSP. The marketing site uses:

default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline';
img-src 'self' data: blob:; frame-ancestors 'none'

No inline scripts, no third-party scripts, fonts, analytics or CDNs. frame-ancestors 'none' prevents other sites from framing Cerebro OS (clickjacking protection).

Egress allowlist

The workspace's connect-src directive permits connections only to its own origin and the named research APIs: Europe PMC, NCBI E-utilities, ClinicalTrials.gov, OpenNeuro and DANDI Archive. Any other destination is refused by the browser. A runtime fetch guard adds a second check inside the application.

OpenAI crawler and agent blocking

As a deliberate product stance, Cerebro OS refuses OpenAI's crawlers and agents at multiple layers:

  • User-agent: requests identifying as GPTBot, ChatGPT-User, OAI-SearchBot or other OpenAI agents are refused by the server.
  • Published IP ranges: requests from OpenAI's published egress ranges are refused regardless of user-agent. The ranges are refreshed from openai.com/gptbot.json, openai.com/chatgpt-user.json and openai.com/searchbot.json.
  • robots.txt: each agent is disallowed from the entire site.
  • Directives: pages carry noai, noimageai robots meta tags and an X-Robots-Tag header.
  • In-app: the workspace cannot call OpenAI API endpoints — they are outside the CSP allowlist and explicitly rejected by the runtime fetch guard.

Other security headers

Responses also set headers such as X-Content-Type-Options: nosniff, a restrictive Referrer-Policy and Permissions-Policy, and HSTS when served over HTTPS. [Confirm against your deployment configuration.]

Deployment

Cerebro OS ships as static files, a zero-dependency Node server, or a Docker container. Because the server holds no user research data, instances are stateless, horizontally scalable and suitable for CDN caching. Self-hosting keeps all traffic inside your own infrastructure.

Compliance status

Cerebro OS does not currently hold HIPAA, SOC 2, ISO 27001 or similar certifications, and is not a medical device. Its local-first architecture is designed so that sensitive data need not leave your machine, but you remain responsible for meeting your institution's data-governance requirements.

Responsible disclosure

If you believe you have found a vulnerability, please email security@cerebro-os.example with steps to reproduce. Please give us reasonable time to investigate before public disclosure, avoid accessing other users' data, and do not run denial-of-service tests.
